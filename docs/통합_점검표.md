## 4. Team 2·3 전달 사항

**공통**

- 상태 읽기는 `TYCOON.app.store.getState()`(또는 `watchView`), 변경은 `TYCOON.app.store.dispatch()`만 사용한다. `TYCOON.app.flow.state`, System, GameState setter를 직접 쓰지 않는다.
- `view()` 필드는 추가만 한다. 필요한 값이 없으면 화면에서 계산하지 말고 팀원 1에게 요청한다.
- `watchView`는 GameState 변경에만 반응한다. meta(`hintsOn`, `seenDialogs`)와 `fatal`은 `store.subscribe`로 받는다.

**Team 2 (월드·에셋)**

- 지역 화면의 검사 표식 신호와 `drawRegion`의 `hit`(`id: 'hall'`)는 진행에 필수다(API명세서 6-5).
- `art.js` 함수 형식과 텍스처 키는 Team 3 화면(`OfficeScene`, `EndingScene`)과 팀원 1의 `BootScene`이 사용한다. 바꾸면 알린다.
- 에셋은 `src/assets/**`에 두고 `ASSETS`에 `index.html` 기준 상대 경로로 등록한다. 외부 주소는 오프라인 ZIP에서 실패한다.

**Team 3 (UI·대화·엔딩)**

- `dispatch()` 실패는 `{ ok: false, error, reason, code? }`다. 분기는 `reason`(`REASON` 또는 `FLOW_REASON`), 표시는 `error` 또는 `reason`별 자체 문구.
- 새 게임은 현재 `TYCOON.app.flow.newGame()` 직접 호출 + `pendingEvents = ['GAME_STARTED']`가 필요하다(`store.newGame()`은 미정).
- 실패한 명령의 결과 이벤트(`CONTRACT_REJECTED`, 미통과 `INSPECTION_COMPLETED`)는 전달되지 않는다. 실패는 반환값으로 처리한다.
- 새로고침 복원 시 UI는 `UIScene.create()`에서 상태로 화면을 구성하고 `pendingEvents`는 비어 있다(대화를 다시 띄우지 않는다).
- 확인 요청: 동료 입장 연출 재생(5장 A), 엔딩 도중 새로고침 동작(5장 B).
