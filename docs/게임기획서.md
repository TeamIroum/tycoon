## 1. 게임 개요

대재난 이후 복구 중인 현대조선. 인력 재편으로 홀로 남은 지방조달청 담당자가 지역의 요청기관과 작은 공방을 연결하며, 사람을 모아 조직을 키우고 지역을 재건하는 PC 웹 경영 시뮬레이션이다.

최상위 목표는 지역 재건이다. 기관 성장과 인재 육성은 재건을 수행하는 수단이고, 차수별 장기사업의 완성이 진행의 이정표다.

| 구분 | 기준 |
| --- | --- |
| 세계관 | 현대조선의 복합재난 이후 / 파주 적성·임진강 일대를 모델로 한 가상 지역 |
| 출발점 | 직원 1명(플레이어), 학당 강당에 머무는 주민 약 20명 |
| 성장 | 개인 → 팀 → 부서 / 고을 재건 → 다리 복구 → 물자·생산·기술 기반 |
| 핵심 재미 | 인재 발견과 육성, 업무 배치, 제약 속 선택, 눈에 보이는 지역 변화 |
| 화면 | 사선 시점 도트풍 지역 화면과 관청 내부 화면을 전환 |
| 첫 버전 | 튜토리얼 구간: 잠자리 마련 → 첫 성과평가 → 첫 동료 선발 (약 10~20분) |

## 2. 세계관과 기관 관계

조달청은 도시를 직접 짓지 않는다. 필요한 물자와 기술의 조달을 지원해 지자체·수요기관의 복구사업이 작동하도록 돕는다.

### 현대조선의 복구 지역

기와지붕·한옥·개량 관복과 현대·근미래 기술이 공존하는 세계다. 대정전에 홍수·산사태가 겹친 복합재난 이후, 옛 관청·학당·장터 주변에 주민과 대피민이 모였고 다리는 끊겨 있다.

숙련 장인과 기술자는 처음부터 정착민 속에 있지만 원자재와 작업 공간이 부족하다. 지역은 피난민 정착지 → 장인·공방 마을 → 산업·연구도시로 발전한다. 지명과 시설은 창작이다.

### 주체별 역할

| 주체 | 게임 속 역할 |
| --- | --- |
| 조달청 본청 | 정책 방향, 전문 지원, 기관 간 협업의 상위 체계 |
| 지방조달청 | 플레이어의 운영 거점. 수요 확인·계약 업무 지원과 조정 |
| 지자체·수요기관 | 복구사업을 추진하고 목적·예산·사용 조건을 제시 |
| 공급기업·공방 | 제품과 기술을 제안하고 계약을 이행하는 독립 주체 |
| 주민 | 시설과 서비스를 이용하고 생활 변화와 후기를 보여주는 주체 |
| 전자조달망 | 공고·제안·계약 정보를 처리하는 시스템 (별도 기관 아님) |

플레이어는 여러 마을을 담당하는 지방 거점 하나를 운영한다. 마을마다 조달청을 새로 짓지 않는다. 인구 유입과 기업 성장은 서비스 개선·일자리·지역 협력의 누적 결과로 표현하며, 계약 한 건이 곧바로 인구를 늘리는 공식은 피한다.

## 3. 첫 버전 범위

첫 버전은 튜토리얼 '주민들의 잠자리 마련'을 완료하고 첫 동료를 선발해 배치하는 지점에서 끝난다. 핵심 업무 흐름(요청 확인 → 계약 → 납품 → 사용)과 이 게임만의 재미인 인재 발견을 한 번씩 온전히 경험하게 하는 것이 목표다.

### 범위를 이렇게 정한 이유

- 끝까지 만들 수 있는 크기로 핵심 루프를 먼저 검증한다.
- 잠자리 과제만으로 끝내면 교육용 콘텐츠처럼 보이므로, 첫 동료 선발까지 넣어 성장의 재미를 맛보기로 보여준다.
- 마지막에 끊어진 다리를 비춰 전체 게임의 방향을 예고한다.

### 포함과 제외

| 영역 | 첫 버전에 포함 | 후속 확장으로 미룸 |
| --- | --- | --- |
| 화면 | 지역·관청 화면 전환, 초기 파손 상태와 잠자리 마련 후 변화 | 중기·후기 지역 모습 |
| 사업 | 침구·매트 과제 1건 | 칸막이·수납함, 학당 책상, 2차 다리 복구 이후 |
| 진행 | 월초 계획 → 진행 → 월말 보고, 2개월 분량 | 월중 결재, 추가 지원 신청 |
| 평가 | 품질·기한·절차 3항목, S~D 종합 등급과 평가 이유 | 세부 점수, 등급 산출 공식의 고도화 |
| 직원 | 후보 3명 공개 → 1명 선발 → 업무석 배치 | 인재 명부, 모집권, 능력 상한·성장 속도, 성장 특성 |
| 육성 | 없음 | 외부 연수, 내부 교육, 피로·휴식 |
| 예산 | 사업예산 하나 (집행 가능액 표시) | 기관 운영비 4구분, 인건비·시설비 |
| 안내 | 나르미·달이 튜토리얼, 마무리 장면 | 상황별 도움말 확장 |
| 저장 | 성공한 진행 명령마다 자동 저장(단일 슬롯), 새로고침 시 자동 복원 | 수동 저장, 결재 직전 저장 |

저장은 새 게임 시작과 성공한 게임 진행 명령마다 브라우저에 자동 저장한다. 월초·월말 전환도 진행 명령이 성공하면 저장된다. 실패한 명령은 저장하지 않는다. 월 중간에 새로고침하면 마지막으로 성공한 명령 이후의 상태로 복원하며, 이미 처리한 계약 예산·평가·채용 결과는 다시 적용하지 않는다. 저장에 실패해도 게임은 계속 진행하고, 저장이 가능해지면 다음 성공 명령에서 다시 저장한다.

예상 플레이 시간은 10~20분으로, 공모전 시연 영상 한 편에 담기는 분량이다. 포함하지 않은 시스템은 잠긴 메뉴로도 노출하지 않는다.

## 4. 튜토리얼 상세 시나리오

플레이어는 2개월 동안 강당에 머무는 주민 20명의 잠자리를 마련하고, 그 성과로 첫 동료를 얻는다.

### 시작 상황

- 재난 대응으로 인력이 흩어진 뒤, 주인공이 지방조달청 현장 거점을 홀로 다시 연다. 관청에는 작동하는 업무석 1개뿐이다.
- 아이를 포함한 주민 약 20명이 학당 강당에 머문다. 식량·생수는 당분간 남아 있고, 기본 응급진료와 임시 위생시설은 작동한다.
- 잠자리가 부족해 일부 주민이 맨바닥에서 잔다. 매트 재고 8개, 침구 재고 12세트가 남아 있다.
- 지역 침구 공방에는 장인·설비·완제품 재고가 남아 있지만, 다리가 끊겨 원단·충전재 공급이 멈춘 상태다. 공방과 학당 사이의 짧은 납품은 가능하다.

### 진행 단계

| 시점 | 단계 | 플레이어의 판단 | 화면에 보이는 결과 |
| --- | --- | --- | --- |
| 1월차 월초 | 거점 재개설 | 나르미의 안내를 듣고 강당 요청서를 연다 | 지역 화면에 학당 표식이 깜빡인다 |
| 1월차 월초 | 요청 확인 | 주민 수·연령 구성과 빠진 규격을 확인한다 | 요청서의 미확인 항목이 채워진다 |
| 1월차 월초 | 재고 확인 | 남은 매트·침구 중 쓸 수 있는 것을 가른다 | 사용 가능한 재고를 기준으로 부족 수량이 확정된다 |
| 1월차 진행 | 준비·계약 | 공고된 조건을 충족하는 제안을 검토한다 | 적격 여부와 판단 근거가 표시된다 |
| 1월차 월말 | 월말 보고 | 계약 완료와 납품 예정을 확인한다 | 달이가 다음 달 할 일을 알려준다 |
| 2월차 진행 | 납품 대응 | 일부 납품 사건에서 일정을 협의한다 | 공방 제작·운송 상태가 바뀐다 |
| 2월차 진행 | 사용 개시 | 검수 결과를 확인하고 사업을 마무리한다 | 강당에 매트가 깔리고 주민이 쉬는 장면 |
| 2월차 월말 | 첫 성과평가 | 품질·기한·절차 결과와 근거를 확인한다 | 추가 정원 1명이 승인된다 |
| 2월차 월말 | 첫 동료 선발 | 후보 3명을 비교해 1명을 뽑고 배치한다 | 두 번째 업무석에 동료가 앉는다 |

### 판단 포인트

혼자 시작하므로 인력 배치로는 고민이 생기지 않는다. 대신 확인 단계에 판단을 둔다.

- **재고 상태**: 매트 8개 중 일부가 젖어 있다. 사용 가능 여부를 확인하지 않으면 부족 수량이 틀리게 잡힌다.
- **사용자 규격**: 아동·고령자용 규격이 따로 필요한지 요청기관에 확인한다.
- **제안 비교**: 가격만 보지 않고 규격 충족·납품 가능 시점을 함께 본다. 업체를 임의로 지정하는 선택지는 없다.

확인을 빠뜨리면 달이가 힌트를 주고 다시 확인할 기회를 준다. 튜토리얼에서는 판단 실수로 진행이 막히지 않는다.

### 가벼운 사건 하나

납품 단계에서 공방의 완제품 재고가 조금 모자라 침구가 일부만 먼저 납품된다. 플레이어는 공방과 나머지 납품 일정을 협의하고, 누구에게 먼저 지급할지 요청기관과 확인한다. 이 사건은 실패가 아니라 보완 과정을 보여주는 장치이며, 기한 안에 해결되면 평가에 불이익이 없다. 이 항목은 v0.7의 "첫 과제에서는 문제를 발생시키지 않는다"는 설계를 바꾼 것이다.

정식 검사는 품목별 최종 실제 납품 수량이 계약 수량과 실제 필요 수량 중 큰 값 이상인지, 계약 규격에 필수 규격이 모두 포함되는지 확인한다. 점검 생략 경로에서는 계약 매트 12개, 실제 필요 14개를 유지하고 TEMP 보완 2개(18만원)로 실제 납품량을 14개로 만든다. 계약 집행액 164만원과 보완비 18만원을 구분해 기록하며 총집행액은 182만원, 초기 예산 300만원 기준 잔액은 118만원이다. 보완은 계약 수량을 변경하지 않는다.

### 첫 동료 후보 예시

후보 3명은 강점이 서로 다르게 무작위로 등장하며, 능력·전문 분야·특성을 선발 전에 모두 공개한다.

| 후보 | 검토 / 기술 / 조정 / 관리 | 전문 분야 | 특성 |
| --- | --- | --- | --- |
| 입문 김도윤 | 4 / 2 / 5 / 3 | 생활물자 | 현장 소통 |
| 숙련 서하린 | 3 / 5 / 2 / 3 | 의료장비 | 시험 결과 분석 |
| 실무 윤가람 | 4 / 3 / 3 / 5 | 시설·토목 | 협업 일정 정리 |

능력은 1~5 예시 척도다. 숙련도가 높다고 항상 유리하지 않게 해, 다음 과제(진료·다리·생활물자)를 상상하며 고르게 한다.

### 마무리 장면

- 맨바닥에서 자던 주민들이 잠자리에 드는 전후 장면과 짧은 후기를 보여준다.
- 관청의 두 번째 업무석에 새 동료가 앉는다.
- 나르미가 다음 과제를 예고하고, 화면이 끊어진 다리와 멈춘 침구 공방을 비춘다.

## 5. 첫 버전 핵심 시스템

첫 버전에는 월 단위 진행, 요청 처리, 성과평가, 첫 모집 네 가지 시스템만 들어간다. 나머지는 7장 로드맵으로 미룬다.

### 5.1 월 단위 진행

기본 진행 단위는 한 달이다. 현실 시간이나 미접속 시간에 따라 진행하지 않는다.

- **월초 계획**: 이번 달 요청과 집행 가능액을 확인하고 확인 작업을 끝낸다.
- **진행**: 계획을 확정하면 한 달의 업무가 진행되고, 사건이 생기면 멈춰서 플레이어에게 묻는다.
- **월말 보고**: 완료·미해결 업무와 다음 달 할 일을 요약한다.

전체 게임의 자동 위임·추천 배치는 직원이 여러 명일 때 의미가 있으므로 첫 버전에서는 빼둔다.

### 5.2 요청 처리 흐름

요청 접수 → 목적·예산·규격 확인 → 계약 준비·평가 → 이행 대응 → 검사·검수 결과 확인 → 사용 개시와 지역 변화 순서로 진행한다. 각 단계에서 계약 방식·평가 기준·검수 책임 주체를 표시한다.

플레이어는 무엇을 확인하고 어떻게 협의할지 결정한다. 필수 규격·평가 기준을 바꾸거나 선호 업체를 마음대로 고르는 선택은 없다.

### 5.3 성과평가

| 항목 | 보는 것 |
| --- | --- |
| 품질 | 규격 충족과 사용 적합성 |
| 기한 | 필요한 시점에 공급되었는가 |
| 절차 | 정해진 기준과 기록을 따랐는가 |

품질·기한·절차 3개 항목을 평가하고, 종합 결과는 S~D 등급으로 표시한다. 첫 버전에서는 세부 점수와 등급 산출 공식을 공개하거나 복잡하게 구현하지 않는다. 등급 문자와 핵심 이유 한 문장만 보여주며, 보완해서 바로잡은 과정도 함께 기록한다.

### 5.4 첫 모집

S~C 등급은 평가 통과로 처리해 추가 정원 1명을 승인하고, 강점이 서로 다른 무작위 후보 3명 중 1명을 선발한다. D 등급은 미통과로 처리하며 시설 개선·추가 정원 승인·후보 생성·채용을 보류하고 평가 결과와 보완 안내를 표시한 뒤 튜토리얼을 종료한다. 등급 산출 공식과 D 도달 조건은 TEMP로 둔다.

- 능력 4종(검토·기술·조정·관리), 전문 분야, 고유 특성을 선발 전에 모두 공개한다.
- 높은 숙련도가 모든 상황에서 우월하지 않도록 설계한다.
- 채용 뒤 처음 드러나는 치명적 약점은 두지 않는다.
- 후보는 한 번 생성한 뒤 저장 데이터에 포함한다. 저장 데이터를 불러오면 같은 후보 목록을 유지한다.
- 실제 공무원 채용 절차를 재현한 것이 아닌 게임상의 인재 확보 장치다.

### 플레이어 캐릭터

플레이어는 현장 운영 책임자로, 일반 직원과 따로 다룬다. 능력은 균형형으로 고정되고 전문 분야는 없다. 기본 업무는 수행할 수 있지만 전문 인력의 가치가 남도록 한다.

## 6. 화면과 마스코트

첫 버전은 지역 화면과 관청 화면을 모두 초기 파손 상태로 보여주고, 잠자리 마련과 첫 동료 배치로 생기는 변화만 그린다. v0.7에 수록한 두 콘셉트 시안(번성한 후반 지역, 직원이 많은 관청)은 분위기와 화면 구성의 참고 자료로 유지한다.

### 화면별 초기 상태와 변화

| 화면 | 초기 상태 | 튜토리얼 후 |
| --- | --- | --- |
| 지역 | 파손·폐쇄 시설, 적은 주민, 멈춘 침구 공방, 끊어진 다리 | 학당 강당에 불이 켜지고 주민 이동이 늘어난다 |
| 관청 | 작동하는 업무석 1개, 부분 복구된 바닥, 닫힌 공간 | 두 번째 업무석이 정비되고 동료가 앉는다 |
| 강당 (튜토리얼 전용 장면) | 맨바닥에 누운 주민 | 매트와 침구가 깔린 강당 |

두 화면은 같은 색감·사선 시점·도트풍을 쓰고 버튼으로 오간다. 어느 화면에서 요청을 열어도 같은 정보로 연결된다.

### UI 배치

- 상단: 날짜(월차)·진행 업무 수·종합 지표
- 우측: 진행 중 요청
- 하단: 주요 메뉴와 화면 전환, 월 진행 버튼

작은 도트 캐릭터와 읽기 쉬운 한국어 UI를 분리해 가독성을 확보한다. 인물은 발 위치를 바닥 좌표에 맞추고 보행 가능한 동선만 이동하며, 바닥의 앞뒤 관계에 따라 가림 순서를 적용한다.

### 마스코트

튜토리얼과 플레이 지원 캐릭터는 조달청 공식 마스코트 나르미와 달이다. 외형은 공식 원본과 활용 안내를 기준으로 맞추고, 아래 역할은 게임 내 설정이다.

| 캐릭터 | 공식 외형 참고 | 첫 버전에서의 역할 |
| --- | --- | --- |
| 나르미 | 흰 황새, 푸른 고글, 붉은 스카프 | 거점 소개, 기관 관계·기준 설명, 사업 결과 해설, 다음 과제 예고 |
| 달이 | 주황빛 다람쥐, 줄무늬와 배낭 | 현재 할 일, 기한·진행 상태, 확인 누락 힌트 |

- 설명은 필요한 순간에만 한다. 모집은 처음 후보를 볼 때 설명한다.
- 마스코트는 확인할 항목과 가능한 다음 행동을 알려주되, 후보나 업체의 정답을 대신 고르지 않는다.
- 건너뛰기·다시 보기·힌트 끄기를 제공하고, 대화창은 주요 버튼을 가리지 않게 배치한다.

## 7. 전체 게임 로드맵

첫 버전은 1차 고을 재건의 도입부다. 전체 게임은 다섯 차례의 장기사업을 거쳐 개인 → 팀 → 부서로 성장하며 지역을 재건한다.

전체 게임 로드맵: 튜토리얼과 5차 장기사업

각 차수는 핵심 사업 완료와 사용 확인, 품질·기한·절차의 최소 기준을 충족하면 다음 단계가 열리고, 추가 정원·공간·전문 업무가 함께 해금된다. 차수별 요구 성과와 결말 조건은 미정이다.

### 후속 확장 시스템 (도입 시점 미정)

v0.7 보완 장에서 설계한 아래 시스템은 첫 버전에서 빼고, 직원이 늘어나는 단계에 맞춰 차례로 도입한다.

| 시스템 | 핵심 내용 |
| --- | --- |
| 자동 위임·업무 추천 | 기존 담당 유지, 신규 업무는 주전문 → 보조전문 → 관련 능력 순으로 추천 |
| 월중 결재·추가 지원 신청 | 큰 예산·범위·일정 변경만 멈춰서 결재, 결과는 다음 달 초 통보 |
| 인재 명부·모집권 | 미선발 후보 보관과 재초청, 명부 인물의 경력 변화 |
| 직원 성장 | 능력별 상한·성장 속도, 주·보조 전문, 성장 특성, 성장 목표 |
| 교육·연수 | 교육실 내부 교육, 1~3개월 외부 집중 연수 |
| 피로·휴식 | 과중 시 피로 누적, 휴식 배치로 회복 |
| 기관 운영비 | 인건비·기본 운영·교육·시설을 사업예산과 분리 |
| 시설 확장 | 업무석·교육실·전문 검토 공간·협업 공간·지역 지원 공간 |

v0.7의 회복 아이템(가상 자양음료)은 공무원 과로를 정당화하는 것처럼 읽힐 수 있어 재검토 대상으로 둔다. 다리 개통·침구 공방 재가동까지만 담는 축소 결말안은 다음 제작 단계의 후보로 보관한다.

## 8. 제도 반영 원칙

실제 제도는 교육용으로 단순화하되, 공정성을 해치는 선택은 게임에 넣지 않는다. 이 장이 문서 전체의 면책 문구를 대신한다.

### 게임 규칙으로 지키는 원칙

- 필수 규격·평가 기준을 임의로 바꾸거나 선호 업체를 고르는 선택은 없다.
- 직원 능력으로 필수 요건 위반을 통과시키거나 법적 책임을 없애지 않는다. 능력은 문제를 일찍 발견하거나 대응 부담을 줄이는 데만 쓰인다.
- 가격만으로 모든 계약을 판단하지 않는다.
- 사업예산은 직원 모집·교육·관청 확장에 전용하지 않는다.
- 기관의 계약 준비 지연을 기업의 납품 지연으로 돌리지 않는다.
- 시범 사용에 성공해도 후속 계약을 자동으로 보장하지 않는다.

### 창작과 실제의 경계

| 실제 자료를 참고한 것 | 게임을 위해 창작한 것 |
| --- | --- |
| 조달청·지방조달청·수요기관·공급기업의 역할 관계 | 지역·인물·기업 이름과 재난 설정 |
| 예산 목적 구분, 계약 이행·검수 원칙 | 무작위 인재 후보, 능력치, 특성 |
| 혁신조달·기업 성장 정책의 방향 | 월 단위 진행, 평가 등급, 해금 조건 |
| 공식 마스코트 나르미·달이의 외형 | 마스코트의 게임 내 역할과 대사 |

파주 적성·임진강은 지리적 모델일 뿐, 실제로 안전한 피난지역이라는 뜻은 아니다. 실제 직위의 결재·인사 권한을 플레이어에게 그대로 부여한 것도 아니며, 사업별 권한과 절차는 시나리오를 쓸 때 공식 자료로 다시 확인한다.

## 9. 결정 사항과 검증 질문

첫 버전 제작을 위해 확정한 주요 사항과 추가 결정이다(2026-11-09~10).

| 항목 | 결정 |
| --- | --- |
| ☑ 종합 지표 | **S~D 등급.** 상세 등급 체계(점수 구간 등)는 첫 버전에서 만들지 않고, 등급 문자와 이유 한 문장만 보여준다 |
| ☑ 가벼운 사건(일부 납품) | **도입** |
| ☑ 판단 포인트 3개와 힌트 방식 | **3개 모두 채택.** 확인을 빠뜨리면 달이가 힌트를 주고 다시 확인할 기회를 준다. 힌트를 꺼도 진행이 막히지 않는다 |
| ☑ 후보 등장 방식 | **무작위.** 한 번 생성한 후보는 저장 데이터에 포함하며, 저장 데이터를 불러온 뒤에도 동일하게 유지한다 |
| ☑ 화면 사양 | 1280×720, 16:9, 픽셀 아트, 마우스 조작. 게임은 GitHub Pages로 배포하고, 제출은 Pages 주소로 연결하는 `게임실행.html`을 ZIP으로 압축 |
| ☑ 공모전 공고 | 확인 완료. 실행파일(html, ZIP) + 시연영상(1분 내외, MP4, 1080p 이상) + 참가신청서 + 개인정보 동의서(팀원 전원). 마감 2026-11-22. 상업적 이용이 허용된 AI 도구만 사용. 마스코트는 사용 가능 확인, 외형은 공식 원본 이미지 기준 |
| ☑ 게임명 | **조달청 타이쿤** (2026-11-10). 배경 지역 이름 '현대조선'은 그대로 쓴다 |

아직 정하지 않은 수치와 규칙(가중치, 등급 공식, 후보 생성 규칙 등)은 `기능정의서.md` 9장에 모아 두었다.

### 본문에서 확인이 필요한 점

- 4장 진행 단계의 매트 부족 수량은 매트 8개 중 젖은 매트 수를 확정한 뒤 계산해야 한다. 사용 가능한 매트 수량은 전체 재고에서 젖은 매트 수량을 뺀 값이며, 부족 수량은 주민에게 필요한 수량에서 사용 가능한 재고를 뺀 값이다. 젖은 매트 수량과 최종 부족 수량은 기능정의서 F-05와 함께 확정한다.
